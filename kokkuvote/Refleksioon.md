##Refleksioon

Git on versioonikontrollisüsteem, mis aitab teil jälgida failide muudatusi ja projektide kallal organiseeritumalt töötada.
See on oluline töö eelmise versiooni taastamiseks ilma olulisi muudatusi kaotamata.
Muudatuste kinnitamine salvestab need lokaalselt ja edastamine saadab need GitHubisse, et need ilmuksid kaughoidlas.
Erinevus seisneb selles, et commit jääb ainult teie arvutisse, samas kui push teeb teie muudatused kättesaadavaks kõigile.
Harud võimaldavad teil projekti eri osadega eraldi töötada ilma põhiversiooni rikkumata.
Pull request on taotlus haru ühendamiseks põhiversiooniga ja see aitab arutada muudatusi enne nende vastuvõtmist.
See on oluline, sest PR võimaldab teil vigu märgata ja oma koodi enne ühendamist parandada.
Git erineb oluliselt failide lihtsast USB-mälupulgale kopeerimisest, kuna see säilitab kogu muudatuste ajaloo, mitte ainult uusima versiooni.
USB-mälupulk on lihtsalt failiedastusvahend, samas kui Git on täieõiguslik tööriist meeskonnatööks ja versioonikontrolliks.
Git on seotud ka projektijuhtimisega, kuna ülesannete abil saab luua ülesandeid ja projektide (Kanban) abil saab jälgida nende edenemist.
See muudab töö struktureeritumaks ja sarnasemaks tegelike IT-töövoogudega.
Ma arvan, et jätkan GitHubi kasutamist, sest see on mugav projektide salvestamiseks, õppimiseks ja portfoolio loomiseks.
See aitab mul oma tööd teistega jagada ja õppida töötama nagu päris arendaja.
Selle projekti kõige raskem osa oli pull requestide ja ühendamiste mõistmine, sest alguses tundus kõik segane.
Lihtsaim osa oli failide loomine ja Markdowni kirjutamine, sest see on selge ja loogiline.
Üldiselt aitas see projekt mul paremini mõista, kuidas tänapäevased arendustööriistad töötavad ja miks Git IT-s nii oluline on.
